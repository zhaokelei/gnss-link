# GNSS Link — 局域网 GPS 共享 / 模拟定位

手机 A 采集 GPS → 通过局域网 UDP 发给手机 B → 手机 B 把它注入为**系统模拟位置**。
B 之后打开高德 / 百度 / Google 地图，会认为自己就在 A 的位置，可以直接导航。
适合没有 GPS 模块的平板、车机、开发板，或者做定位相关的测试。

基于开源项目 [wxip/gnsslink](https://github.com/wxip/gnsslink) 重做。

```
A 手机（有 GPS）                 Wi-Fi / 热点                 B 手机（无 GPS 也行）
┌──────────────────┐                                      ┌──────────────────┐
│ LocationManager  │  ── UDP 7007 ──►  ┌──────────┐  ◄──  │ MockLocationEngine│
│  gps / network   │                   │ 路由器/AP │       │  addTestProvider  │
│  1Hz 采样        │  ◄── ACK ───────  └──────────┘  ──►  │  setTestProvider… │
└──────────────────┘                                      └──────────────────┘
```

## 和参考项目的差别

参考项目 `gnsslink` 的核心只有 145 行 Java，思路完全正确，但只能算 demo。这一版做了这些事：

| 问题 | 参考项目 | 本工程 |
|---|---|---|
| 息屏/切后台 | 逻辑写在 Activity，进程被冻结后定位就停 | 两个前台服务 + 常驻通知，可长期运行 |
| 配对方式 | 手动输入 B 的内网 IP | UDP 广播自动发现，也支持手动指定 IP 兜底 |
| 鉴权 | 无，同网段任何设备都能往你手机灌坐标 | 房间码校验，不匹配直接丢弃 |
| 模拟位置授权 | 捕获 `SecurityException` 后弹个 Toast | 主动用 AppOps 检测 + 引导跳转开发者选项 |
| 注入 provider | 只顶替 `gps` | `gps` + `network`，兼容只读 network 的车机/平板 |
| 链路质量 | 看不到 | 实时显示帧率、往返延迟、丢包率 |
| 断线 | 挂了就挂了 | 心跳 + 自动重新发现 + 服务被回收后自恢复 |
| 异常 | `throw new RuntimeException(e)` 直接崩 | 全链路 try/catch，失败降级为日志 |
| 语言/构建 | Java、AGP 8.3.0-alpha07、Gradle 8.4-rc-2 | Kotlin、AGP 8.3.2、Gradle 8.4 正式版 |

## 快速开始

### 1. 编译

用 Android Studio 直接打开 `gpslink/` 目录，或者命令行：

```bash
cd gpslink
./gradlew assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`local.properties` 里的 `sdk.dir` 指向本机 Android SDK，换机器需要改。
要求：JDK 17+、compileSdk 34、minSdk 26。

> 如果卡在 `Downloading https://services.gradle.org/distributions/gradle-8.4-bin.zip`，
> 说明该域名访问不通，把 `gpslink/gradle/wrapper/gradle-wrapper.properties` 里的
> `distributionUrl` 换成腾讯镜像：
> `https\://mirrors.cloud.tencent.com/gradle/gradle-8.4-bin.zip`
>
> 本机已经编译通过，产物在 `gpslink/app/build/outputs/apk/debug/app-debug.apk`（5.7 MB），
> 可以直接 `adb install`。

### 2. B 手机（接收端）先授权模拟位置

这一步**必须手动做，任何应用都无法用代码绕过**：

1. 设置 → 关于手机 → 连点「版本号」7 次，打开开发者选项；
2. 设置 → 系统 → 开发者选项 → **选择模拟位置信息应用** → 选中 `GNSS Link`；
3. 回到 App，点「开始接收」，允许定位权限和通知权限。

如果没做第 2 步，点「开始接收」会直接弹出蓝色提示卡片并把你送到开发者选项页面。

### 3. 使用

1. 两台手机连同一个 Wi-Fi（或 A 开热点、B 连上）；
2. 房间码填一样的（默认 `8888`），端口保持 `7007`；
3. B 点「开始接收」→ 状态显示「接收端 运行中 · 等待中…」；
4. A 点「开始共享」→ 几秒内两端都会显示对方 IP；
5. B 打开任意地图 App，位置就是 A 的位置。

A 端「接收端 IP」留空即自动发现。如果路由器开了 AP 隔离 / 客户端隔离，
广播会被拦掉，这时手动填 B 的 IP（在 B 的 App 里能看到，或在路由器后台查）。

## 怎么确认 B 用的是 A 的定位

接收端跑起来后，界面会出现一张「定位校验」卡片：

```
注入值    33.592432, 114.078952
系统回读  gps · mock=true · 33.592432, 114.078952
结论      系统正在向所有 App 提供模拟位置（偏差 0.0 m）
```

- **注入值**：从 A 收到的坐标；
- **系统回读**：B 自己再问一次系统「你现在在哪」（`LocationManager.getLastKnownLocation()`），
  拿到的就是高德 / 百度 / Google 地图会拿到的**同一个值**；
- **mock=true**：系统把这个位置标记为模拟位置，第三方 App 的 `Location.isMock()` 也会是 true；
- **偏差**：两者应该接近 0。偏差大说明注入没生效。

**为什么光看「坐标」不算证据**：两台手机放在一起时坐标本来就差不多；而且旧版本停止后不清空，
界面会残留上一次的值。必须看「系统回读 + mock 标志」。

另外两个独立验证方法：

**物理验证（最直观）**：拿着 A 走开 20 米，B 的坐标应该跟着变，而 B 自己没动。
反过来只把 B 拿走，坐标不变——那就确认了。

**命令行**：

```bash
adb shell dumpsys location | grep -i mock
```

能看到 `mock` 字样，说明系统里确实有测试 provider 在供数。

## 定位数据字段

界面上「定位数据」卡片里各项的含义：

| 字段 | 含义 | 来源 |
|---|---|---|
| 坐标 | WGS-84 经纬度 | `getLatitude()` / `getLongitude()`，未做 GCJ-02 偏移 |
| 精度 | 水平定位精度（米），越小越好 | `getAccuracy()` |
| 高度 | 海拔（米） | `getAltitude()` |
| 速度 | 米/秒，括号内是 km/h | `getSpeed()` |
| 运动方向 | 0~360°，附八方位，0=北 90=东 | `getBearing()` |
| 源点年龄 | 这帧数据从 GPS 产生到现在过了多久 | 见下 |

**源点年龄为什么不是直接减时间戳**：两台手机时钟差几秒就会算错。所以发送端在发帧时，
把「这一帧已经老了多久」（`now - location.time`）一起塞进包里；接收端用
`这个值 + 从收到到现在过去的时间` 得出真实年龄。全程只用本机单调时钟，两端时间不同步也不影响。

超过 3 秒会标「数据偏旧」，通常意味着发送端 GPS 丢星，或者链路卡住了。

## 采样频率与注入频率

两个不同的东西，别混：

- **采样频率（发送端）**：A 多久读一次 GPS。可选 1 / 2 / 5 / 10 Hz。
- **注入频率（接收端）**：B 多久往系统写一次位置。可选 1 / 5 / 10 Hz，默认 **10 Hz**。

**1 Hz 够不够？** 够。真机 GPS 本身就是 1 Hz，高德 / 百度 / Google 地图都按 1 Hz 设计：
120 km/h 时每帧 33 米，导航软件靠 `speed` + `bearing` 推算，不会卡。

**那为什么模拟定位看起来一顿一顿？** 真机的 1 Hz 会经过 FusedLocationProvider 与 IMU 融合平滑，
而注入的测试 provider 不走这条路，位置是每秒"跳"一次的。所以这是**平滑问题，不是采样率问题**。

**正确做法不是把采样率拉到 10 Hz**（很多手机的 GPS 芯片只输出 1 Hz，拉了也没用），
而是**接收端插值**：B 拿到 1 Hz 的帧后，按 `speed` + `bearing` 在两次帧之间直线外推，
以 10 Hz 写进系统。输入还是 1 Hz，但系统看到的是连续移动。

外推有三层保护：

1. **速度 < 0.5 m/s 不外推** —— 站着不动时点位就停住，不会漂；
2. **最多外推 3 秒** —— 断流时不会沿最后方向一直飞出去；
3. **换帧残差 400ms 线性衰减** —— 预测点和真实点的差被慢慢吃掉，不会每秒"跳一下"；
   残差超过 100 米（A 端瞬移）则直接跳过去，不做平滑。

**代价**：注入 10 Hz 时每秒约 20 次 binder 调用（gps + network 各 10 次），耗电可以忽略。
外推本质是推算，转弯时会有几米偏差，下一秒被真实帧纠正。

## 检测本机采样上限

「频率设置」里点 **检测本机上限**：App 会以 50ms 的间隔申请 GPS 更新，统计连续两次回调之间
`Location.elapsedRealtimeNanos` 的差值，取中位数换算成频率。

- 用 `elapsedRealtimeNanos` 而不是回调到达时间 —— 主线程可能被别的任务卡住，到达时间会偏大；
- 需要室外或窗边。室内没星时会提示"样本太少"；
- 这是**实测值**，受环境影响，不是硬件规格。

如果实测就是 1 Hz，说明 GPS 芯片只输出 1 Hz，采样频率调到 5/10 Hz 也没意义 ——
这时候只能靠接收端插值来补平滑。

## 蓝牙传输

传输方式可以在 **局域网 / 蓝牙** 之间切换。蓝牙走经典 RFCOMM，不用 BLE：

- 1~10 Hz 的定位帧每包约 250 字节，RFCOMM 带宽（~100 KB/s）绰绰有余；
- 不需要 GATT 那套 service / characteristic / MTU 协商，代码少一半；
- 断线重连只要重新 `connect()`。

**帧格式**：换行分隔的 JSON（NDJSON）。RFCOMM 是字节流，不像 UDP 有天然的消息边界，
所以每帧后面加 `\n`，接收端用 `readLine()` 切分。

**用法**：

1. 两台手机先在**系统蓝牙设置**里配对（本 App 只列已配对设备，不做扫描，
   这样可以省掉 `BLUETOOTH_SCAN` 和它附带的一堆定位权限纠缠）；
2. 发送端切到「蓝牙」→「选择设备」→ 选中接收端；
3. 接收端切到「蓝牙」→「开始接收」；
4. 发送端点「开始共享」，会自动连过去。

**注意事项**：

- 有效距离约 10 米（无遮挡），隔墙衰减明显；
- 带宽不是瓶颈：1 Hz 约 250 B/s，10 Hz 约 2.5 KB/s；
- Android 12+ 需要 `BLUETOOTH_CONNECT` 运行时权限，切到蓝牙模式时才会申请。

## 卫星信号

仿 GPS Test 的样式：每行一颗卫星，左边是星座标签（按星座着色）、卫星编号、C/N0 信号条，
右边是数值和频段。

数据来自 `LocationManager.registerGnssStatusCallback()` 的 `GnssStatus`：

| 显示项 | API | 说明 |
|---|---|---|
| 星座 | `getConstellationType` | GPS / 北斗 / GLONASS / Galileo / QZSS / SBAS / NavIC |
| 编号 | `getSvid` | 显示成 `G12` `C19` `R07` 这种 |
| 信号强度 | `getCn0DbHz` | 载噪比 dB-Hz，40 以上算强；条长按 /50 归一 |
| 载波频率 | `getCarrierFrequencyHz` | **Android 11（API 30）起才有**，低版本显示 `—` |
| 高度角 / 方位角 | `getElevationDegrees` / `getAzimuthDegrees` | 已采集，暂未画天顶图 |
| 是否参与定位 | `usedInFix` | 参与定位的排前面、字色更深 |

排序规则：参与定位的优先，其次按 C/N0 降序 —— 和 GPS Test 一致。

频段由载波频率反推：1575.42 MHz → L1，1176.45 MHz → L5，1561.098 MHz → B1I，
1207.14 MHz → B2I，1602 MHz → G1。图下方的图例会列出当前实际用到的频段和精确频率。

### 单频 / 双频 / 三频 / 四频

统计当前**实际收到的不同载波频率**个数（按 0.1 MHz 粒度去重）：1 个 → 单频，2 个 → 双频，
3 个 → 三频，4 个 → 四频。

注意这是「有几个不同频点在用」的字面定义，不是厂商宣传口径。比如同时收到 GPS L1（1575.42）
和北斗 B1I（1561.10），按这个定义算双频；GPS L1 + L5 也算双频。图例会列出具体是哪几个频点，
可以自己判断。设备不上报载波频率时（Android 11 以下）显示「频段未知」。

### 接收端也能看到发送端的卫星

发送端每 **2 秒**发一条 `SAT` 报文（不跟定位帧同频，因为卫星状态变化慢），
带全部卫星的编号、星座、C/N0、频率、是否参与定位。接收端收到后渲染同一套信号条，
标题标明「来自 192.168.1.17」。

报文用数组压缩成 `[svid, 星座, cn0, 频率MHz, 是否定位]`，30 颗卫星约 800 字节，
远小于 UDP 单包 1400 的上限；蓝牙走流式也无压力。

## 关于让高德 / 百度读取卫星数

这里必须说清楚，避免期望落空：

- **卫星列表无法伪造。** `GnssStatus`（画天顶图、列卫星用的那个 API）由 GNSS 硬件抽象层直出，
  模拟位置注入不进去。任何读 `GnssStatus` 的应用，拿到的都是本机真实（或已停止）的 GNSS，
  不可能是 A 的数据。
- **唯一能伪造的是 `Location.getExtras()`。** AOSP 的 GNSS provider 会往里塞
  `satellites` / `meanCn0` / `maxCn0` 三个字段，本工程在注入时已经把这三个补上了
  （取发送端的值），这是业界通行约定。
- **但高德 / 百度地图的界面本身不显示卫星数。** 导航时它们只按信号强弱做提示，
  不会把「12 颗星」画出来。所以即使 extras 生效，你在它们的界面上也看不到。
- **能看到的场景**：GPS Test / GPS Status 这类工具，以及自己写代码读
  `location.extras.getInt("satellites")`。

验证 extras 是否真的挂上去了：

```bash
adb shell dumpsys location | grep -i "satellites"
```

## 后台保活

导航时手机经常要息屏，保活是这类工具能不能用的关键。本工程做了四层：

| 措施 | 作用 |
|---|---|
| **前台服务 + 常驻通知** | 进程不会被系统冻结；通知内容实时显示对方地址和帧率，也是服务的"存活凭证" |
| **PARTIAL_WAKE_LOCK** | 前台服务挡不住 CPU 挂起。息屏后 CPU 一睡，定位回调和 10Hz 注入定时器都会停摆，所以两个服务都自己持锁 |
| **电池优化白名单** | 界面「电池优化」一行可以点击直接跳到系统授权页。这一条对国产 ROM 最有效 |
| **START_STICKY + 参数持久化** | 服务被杀后系统会重启，重启时 intent 为 null，从 SharedPreferences 恢复端口、房间码、采样率、传输方式 |

另外 `onTaskRemoved` 只记录日志、不主动停止——从最近任务划掉时，服务继续跑。

**通知权限**：Android 13+ 需要 `POST_NOTIFICATIONS`。即使拒绝，前台服务本身仍然工作，
只是通知栏看不到，系统的保活优先级也会降低，建议授予。

**国产 ROM 还需要手动放行**：MIUI / ColorOS / EMUI / OriginOS 等除了电池优化，还要在
「自启动管理」「后台弹出界面」「锁屏显示」里单独允许本应用，否则仍可能被清理。

## 稳定性上的取舍

这些是已知的、有意接受的问题：

- **外推最多 1.5 秒**。断流时如果一直沿最后方向推，120 km/h 的车 3 秒能飘出 100 米。
  宁可停住也不要让蓝点飞出道路。
- **进程被 ROM 强杀时可能残留测试 provider**。下次打开 App 时会自动清理
  （`MockLocationEngine.release()` 不依赖内部状态，对两个 provider 都尝试移除）。
- **`Location.isMock()` 恒为 true**。银行、考勤打卡、网约车司机端等会主动拒绝，这是系统设计，绕不过。
- **注入 10 Hz 是 binder 调用密集操作**。接收端约 20 次/秒（gps + network 各 10 次），
  实测耗电可以忽略，但确实比 1 Hz 高。
- **FusedLocationProvider 与测试 provider 的交互依赖厂商实现**。绝大多数机型正常，
  个别 ROM 上 FLP 可能仍会混入传感器推算，表现为转弯时略有滞后。

## 连不上怎么排查

界面现在会显示 **本机 IP、对方在线状态、已收/已发包数**，按这个顺序看就能定位到具体哪一段断了：

| 现象 | 说明 | 处理 |
|---|---|---|
| 接收端「已收 0 包」 | 网络层完全不通 | 见下面第 1 条 |
| 接收端「已收 N 包」，发送端「已收 0 包」 | 去程通、回程被拦 | 见第 2 条 |
| 两端都有包，但「对方：无响应」 | 单向丢包 / 探活超时 | 见第 3 条 |
| 坐标正常，地图不动 | 注入没生效 | 见第 4 条 |

**1. 一个包都收不到**

- 两台手机是否连**同一个** Wi-Fi？对比两端的「本机 IP」，前三段要一致（如 `192.168.1.x`）。
- 路由器是否开了 **AP 隔离 / 客户端隔离 / 访客网络**？这是最常见的原因，现象是能上网但两台设备互相看不见。
- 手机同时开了 Wi-Fi 和蜂窝，广播可能从错误的网卡出去。关掉移动数据再试。
- **兜底方案**：接收端界面显示的 `本机 IP` 就是要填的地址。在发送端「接收端 IP」里填上它，跳过自动发现。

**2. 接收端能收，发送端收不到回执**

接收端回包的源端口是 7007，部分路由/防火墙会拦非请求方向的包。多半还是 AP 隔离。
如果只是偶尔丢，不影响使用——新版不再因为丢几个包就断开连接。

**3. 对方显示「无响应」**

通常是某端被系统省电策略限制了。把两台手机都加入「电池优化白名单」，
国产 ROM 还要在「自启动管理」「后台运行」里放行本应用。

**4. 坐标对了但地图不动**

- 确认 B 端已在开发者选项里选中本应用为「模拟位置信息应用」；
- `adb shell dumpsys location | grep -i mock` 看系统里有没有 mock provider；
- 部分 App（银行、考勤、网约车司机端）会检测 `Location.isMock()` 并主动忽略，这不是 bug。

## 协议

单包 JSON，UDP，默认端口 7007，最大 1400 字节（不拆包、不重传）。

| 类型 | 方向 | 作用 |
|---|---|---|
| `WHO` | A → 广播 | 寻找接收端 |
| `HERE` | B → A | 应答，带设备名 |
| `LOC` | A → B | 一帧定位数据 |
| `ACK` | B → A | 回执，回传 A 的时间戳用于算 RTT |
| `BEAT` | B → A | 每 2 秒主动心跳，避免丢包被误判成掉线 |
| `SAT` | A → B | 每 2 秒一次的卫星快照（编号/星座/CN0/频率/是否定位） |
| `BYE` | B → A | 拒绝（房间码不符等） |

**蓝牙模式**下没有 `WHO` / `HERE`（连接本身就是配对），只走 `LOC` / `ACK` / `BEAT`，
报文内容完全一致，只是把 UDP 单播换成 RFCOMM 字节流，每帧以 `\n` 结尾。

```json
{"v":1,"t":"LOC","sid":"8888","seq":128,
 "lat":31.230416,"lon":121.473701,"alt":12.5,
 "acc":4.2,"spd":0.0,"brg":0.0,
 "vacc":3.0,"sacc":0.5,"bacc":10.0,
 "tms":1760702400123}
```

坐标是 **WGS-84**，原样透传，不做任何坐标系转换。原因见 `docs/技术方案.md`。

## 已知限制

- **必须在同一局域网**，跨公网需要加中继（WebSocket / MQTT），协议层预留了 `v` 字段便于升级。
- **无法绕过模拟位置授权**，这是 Android 的安全设计。已 root 的设备可以用
  `adb shell appops set top.wxip.gpslink android:mock_location allow` 免手动设置。
- 部分 App 会检测 `Location.isMock()` 并拒绝服务（银行、考勤打卡、网约车司机端、部分运动 App）。
- 模拟位置没有真实卫星信号，依赖 GNSS 惯导融合的导航在转弯时会略滞后。
- 仅用于自用测试与无障碍场景。位置信息属于敏感个人信息，向他人共享需取得同意；
  用于考勤代打卡、刷单、游戏外挂等可能构成违规甚至违法。
